L10 调试与性能

coredump+gdb · addr2line · perf

1. coredump 与 gdb

coredump（核心转储）：程序异常退出时，把内存、寄存器、堆栈等状态保存到文件，供调试分析。

  • 开启： ulimit -c unlimited。
  • 调试： gdb ./a.out core，常用 bt 看调用栈。
  • 嵌入式中常在开发环境用 gdb + gdbserver 远程调试目标板。
$ ./myapp
Segmentation fault (core dumped)
$ gdb ./myapp core
(gdb) bt           # 查看调用栈
(gdb) info locals  # 查看局部变量

快速检查

程序崩溃后，coredump 文件里保存了什么？

coredump 是崩溃瞬间进程状态的快照，用于事后分析。

2. gdb 常用命令

命令作用
break main在 main 函数处设置断点
run运行程序
next / step单步执行（不进入/进入函数）
continue继续运行到下一个断点
print var打印变量值
backtrace / bt查看调用栈
info registers查看寄存器

快速检查

gdb 中查看函数调用栈的命令是？

backtrace 或 bt 用于查看当前调用栈。

3. addr2line

当程序日志只打印了一个崩溃地址，而目标板没有调试符号时，可以用 addr2line 把地址转换回源码文件名和行号。

# 编译时保留调试信息
$ gcc -g -o app main.c

# 把地址转换为源码位置
$ addr2line -e app 0x4005b6
main.c:42

嵌入式中常把地址日志导出，在主机用带符号的 ELF 文件反查行号。

快速检查

addr2line 的功能是？

addr2line 用调试符号把地址映射回源码位置，便于定位崩溃点。

4. perf 性能分析

perf 是 Linux 内核自带的性能剖析工具，可以查看：

  • CPU 热点函数（perf top / perf record -g）。
  • 缓存命中率、缺页、分支预测等硬件事件。
  • 火焰图（Flame Graph）：直观显示时间花在哪些调用栈上。
$ perf record -g ./myapp
$ perf report

快速检查

perf 主要用于？

perf 通过性能计数器分析 CPU 热点和硬件事件。
