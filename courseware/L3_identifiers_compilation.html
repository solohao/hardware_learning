1. static 的三种用法

static 根据修饰位置不同，含义不同：

  • 全局变量/函数前的 static：只在当前文件可见，避免与其他文件重名冲突（内部链接）。
  • 函数内的 static 局部变量：只初始化一次，生命周期贯穿整个程序，值跨调用保留。
  • C++ 类成员 static：属于类本身，不依赖对象。
void count() {
    static int c = 0;  // 只初始化一次
    c++;
    printf("%d\n", c);
}

快速检查

函数内 static int x = 0; 的 x 有什么特点？

函数内 static 局部变量生命周期与程序相同，只初始化一次，值跨调用保留。

2. extern 与多文件

extern 用于声明一个在其他地方定义的变量或函数，告诉编译器“符号在其他地方”。

  • 变量只能在一个 .c 文件中定义，其他文件用 extern 声明。
  • C++ 中 extern "C" 用于关闭名称修饰，让 C++ 代码调用 C 函数。
// file1.c
int g_val = 10;

// file2.c
extern int g_val;  // 声明，不是定义
void foo() {
    printf("%d\n", g_val);
}

快速检查

在 file2.c 中使用 file1.c 定义的全局变量 int g，应该怎么写？

用 extern 声明外部定义的全局变量，避免重复定义。

3. #define、typedef 与 const

关键字/指令作用注意
#define预处理期文本替换无类型检查，可能因括号缺失导致意外
typedef给已有类型起别名有类型语义，编译器能检查
const修饰只读指向常量的指针 vs 常量指针要分清
#define PINT int *       // 文本替换
typedef int* PINT;       // 类型别名
const int *p;            // p 指向的 int 不能改，p 本身可以改
int * const p;           // p 本身不能改，指向的 int 可以改

快速检查

下面哪个是“类型安全的别名”？

typedef 是编译器理解的类型别名，有类型检查。

4. 编译四阶段

C/C++ 程序从源码到可执行文件通常经历四个阶段：

  1. 预处理：gcc -E，展开宏、头文件包含、条件编译，生成 .i。
  2. 编译：gcc -S，把预处理后的代码转成汇编，生成 .s。
  3. 汇编：gcc -c，把汇编转成目标文件 .o（机器码）。
  4. 链接：gcc，把多个 .o 和库合并为可执行文件，解析符号地址。

快速检查

哪个阶段负责把多个 .o 文件合并并解析未定义符号？

链接阶段合并目标文件和库，把符号引用解析为实际地址。
