L2 存储布局

内存碎片 · 内存对齐 · struct vs union · 位域

1. 内存碎片

动态分配的堆中，已释放的内存块如果大小不一、位置分散，就可能出现“总空闲足够，但连不起来”的情况，这就是 外部碎片。

  • 外部碎片：堆中散落的小空闲块总和够大，但都不连续，导致大块分配失败。
  • 内部碎片：分配器给用户的块比实际请求大（对齐、管理头等），多余部分在块内浪费。
  • 嵌入式中常用固定大小内存池、slab 分配器来减少碎片。

快速检查

“总空闲内存够，但没有连续大段空间”描述的是哪种碎片？

这是外部碎片：空闲总量足够，但被已分配块隔开，无法合并。

2. 内存对齐

CPU 按固定字节数（如 4、8）读取内存。若一个 int 从奇数地址开始，可能跨两次总线访问，某些架构甚至直接触发异常。

  • 对齐值：多数 32 位系统 int 对齐到 4 字节，64 位指针/double 对齐到 8 字节。
  • 编译器会在 struct 成员间插入填充字节（padding），让各成员对齐。
  • 可用 #pragma pack 或 __attribute__((packed)) 取消/改变对齐，以空间换速度或避免协议解析错误。

快速检查

内存对齐的主要目的是什么？

对齐让 CPU 一次读出完整数据，部分嵌入式架构对未对齐访问会直接报错。

3. struct vs union

struct 把多个成员“排排坐”，union 让多个成员“共享同一块内存”。

struct S {
    char c;   // 1B
    int i;    // 4B（对齐后通常 char 后补 3B）
};

union U {
    char c;
    int i;
    double d; // 最大成员决定 union 大小
};
  • struct：所有成员同时存在，内存依次排列，可能有 padding。
  • union：所有成员共享起始地址，写入一个成员后再读另一个成员会得到未定义解释。

快速检查

在 64 位系统上，`union { char c; int i; double d; }` 的大小通常是多少？

union 大小由最大成员决定；double 通常为 8 字节，所以 union 占 8 字节。

4. 位域

位域允许把 struct 成员精确指定到若干 bit，常用于寄存器映射、协议标志位等内存紧张的场合。

struct Flags {
    unsigned int power : 1;  // 0/1
    unsigned int mode  : 3;  // 0-7
    unsigned int       : 4;  // 保留 4bit
    unsigned int status: 8;
};
  • : 后面的数字表示该成员占几个 bit。
  • 位域的大小、排布（从高位还是低位开始）由编译器决定，跨平台时要谨慎。
  • 不能对位域取地址（&f.power 非法），因为它可能不占用完整字节。

快速检查

unsigned int a : 3; 最多能表示多少个不同值？

3 个 bit 可表示 2^3 = 8 个不同值，范围 0~7。

5. 综合练习：struct 大小计算

下面这个结构体在 64 位 GCC 上通常占多少字节？

struct Example {
    char  a;   // 1
    int   b;   // 4
    short c;   // 2
};
  • char 后补 3B，让 int 从 4 字节边界开始。
  • short 占 2B，但 struct 整体大小要补齐到最大成员（int）的对齐边界，所以末尾再补 2B。
  • 用 sizeof(struct Example) 验证，不要心算猜。

快速检查

上述 struct Example 在典型 64 位编译器下大小是？

1 + 3(pad) + 4 + 2 + 2(pad) = 12 字节。
