L1 内存与生命周期

地址空间全图 · 栈 vs 堆 · 野指针 · 内存泄漏

1. 地址空间全图

一个 32/64 位进程看到的虚拟地址空间可以分成几个区域，每个区域职责不同。

  • Text：机器指令，只读。
  • Data：已初始化的全局/静态变量。
  • BSS：未初始化的全局/静态变量，启动时清零。
  • Heap：动态内存，由程序员申请/释放。
  • Stack：局部变量、函数参数，自动管理。
  • Kernel：用户态不可直接访问，系统调用进入。

快速检查

未初始化的全局变量存放在哪个段？

BSS 段存放未初始化的全局/静态变量，程序启动时会被清零。

2. 栈 vs 堆

栈和堆是程序运行时使用最频繁的两块内存，但管理方式和生命周期完全不同。

特性栈 Stack堆 Heap
分配时机进入函数/作用域时自动分配程序员显式 malloc/calloc
释放时机离开作用域自动释放程序员显式 free，或程序结束
大小较小（通常 1-8 MB）较大，受虚拟内存限制
典型用途局部变量、函数参数运行时大小未知的数据、大对象、跨函数数据
常见错误栈溢出内存泄漏、野指针、越界

快速检查

函数中的普通局部变量存储在哪里？

普通局部变量在栈帧中分配，函数返回时自动释放。

3. malloc / free 用法

malloc 从堆申请 size 字节，返回 void * 指针；申请失败返回 NULL。

int *p = malloc(sizeof(int) * 10);
if (p == NULL) {
    // 处理失败：退出或重试
    return -1;
}
for (int i = 0; i < 10; i++) {
    p[i] = i;
}
free(p);   // 释放
p = NULL;  // 避免野指针
  • 用 sizeof 而不是写死字节数，保证可移植。
  • malloc 不初始化，内容是未定义的。
  • calloc 会清零内存；realloc 调整已分配块大小。

快速检查

malloc 失败时返回什么？

申请失败时 malloc 返回 NULL，调用方必须检查。

4. 野指针与防范

野指针是指向已被释放或无效内存的指针，使用它会导致未定义行为。

常见成因

  • free 后置空：free(p); 后 p 还保存旧地址。
  • 越界访问：读写超出 malloc 范围。
  • 重复释放：free(p); free(p); 破坏堆结构。
  • 返回局部变量地址：函数结束后栈帧被回收。
int *p = malloc(sizeof(int));
*p = 42;
free(p);
// p 此时是野指针，但保存的地址数字还在
p = NULL;  // 置空，明确它已不可用

// 错误示例
int *q = malloc(sizeof(int));
free(q);
free(q);  // double free，未定义行为

快速检查

free(p) 之后，为了避免产生野指针，通常应做什么？

free 后把指针置 NULL，后续 if(p) 等判断就不会误用。

5. 内存泄漏

申请了堆内存但没有 free，且没有任何指针再指向它，就会造成内存泄漏。长时间运行的嵌入式设备尤其要注意。

void leak_example() {
    while (1) {
        char *buf = malloc(1024);
        // 使用 buf ...
        // 忘记 free(buf); -> 每轮循环泄漏 1KB
    }
}

嵌入式系统内存有限，泄漏会导致 OOM、任务被杀或系统重启。

  • 每个 malloc 都要有对应的 free。
  • 异常路径（return、goto、错误处理）中也要释放。
  • Linux 可用 valgrind 检测内存泄漏。

快速检查

下面哪种情况会导致内存泄漏？

丢失指针且未释放，堆块就无法回收，造成泄漏。
