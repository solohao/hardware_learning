1. 交叉编译

在 PC（x86）上编译出能在嵌入式 ARM 等平台运行的程序，称为交叉编译。

  • 编译器命名通常形如 arm-none-eabi-gcc、aarch64-linux-gnu-gcc。
  • 需要目标平台的头文件、库、链接脚本和启动文件。
  • 编译产物不能在本机直接运行，需要烧录或放到目标设备。
arm-none-eabi-gcc -mcpu=cortex-m4 -o firmware.elf main.c

快速检查

交叉编译器运行在哪个平台上？

交叉编译器在开发主机上运行，生成目标平台的可执行代码。

2. 静态库 vs 动态库

特性静态库 .a动态库 .so/.dll
链接时机编译时复制到可执行文件运行时加载
体积可执行文件大，但无运行时依赖可执行文件小，多个程序共享
更新重新编译才能更新替换 .so 即可（接口兼容）
嵌入式常用常用资源足够时可用

快速检查

哪种库在编译时被完整复制到可执行文件中？

静态库在链接阶段被复制到可执行文件，运行时不需要单独库文件。

3. DMA 与 Cache

  • DMA（Direct Memory Access）：外设和内存之间直接传输数据，不需要 CPU 逐字节搬运。
  • Cache 一致性问题：CPU 可能把数据留在缓存中，而 DMA 看到的是物理内存中的旧数据。
  • 解决：DMA 前对 cache 做 clean/flush（把缓存写回内存），DMA 后 invalidate（让缓存失效，重新读内存）。
// DMA 前：确保内存有最新数据
__builtin___clear_cache(dst, dst + size);  // GCC 示例
// DMA 后：让 cache 失效，CPU 重新读取

快速检查

DMA 开始前通常需要对 cache 做什么？

DMA 看到的是物理内存，如果 CPU cache 里有最新数据，必须先写回。

4. 左值与右值

  • 左值 lvalue：能取地址、可被赋值，如变量、数组元素、解引用后的指针。
  • 右值 rvalue：临时值，不能取地址，如字面量、表达式结果、函数返回值（非引用）。
int a = 5;
a = 10;      // a 是左值
// 5 = a;    // 错误：5 是右值

int *p = &a;
*p = 20;     // *p 是左值

int b = a + 1;  // a+1 是右值

快速检查

下面哪个是左值？

变量有固定地址，可被赋值，是左值。
